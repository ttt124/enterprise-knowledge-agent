# AI 辅助使用说明

## 使用方式

本次采用 AI 辅助开发方式。我使用 Codex 辅助需求梳理、程序实现、测试和文档整理，并在交付材料中保留验证记录及已知限制。Codex承担开发辅助，项目运行时的知识问答模型为 `deepseek-flash`。

## 本人参与事项

- 确定第3题作为作答方向，并确认使用 Python CLI。
- 申请模型 API，在本机配置密钥与调用参数，完成 GitHub 账号登录。
- 查看提交材料，对评审入口、文档受众、附件范围和用时说明提出修改要求。
- 提供约3小时的投入时长估算。未按各环节单独计时，因此不拆分具体工时或计算人工与 AI 的百分比。

## AI 辅助范围

| 环节 | 辅助内容 |
| --- | --- |
| 需求与方案 | 拆解验收场景，提出模块划分、工具接口及技术取舍建议 |
| 程序实现 | 生成并迭代模型接入、工具循环、检索、引用校验、错误处理及CLI代码 |
| 测试与验证 | 生成测试、评估脚本及合成资料，通过辅助工具执行测试和真实模型用例，检查运行记录 |
| 问题修正 | 分析冲突回答越界、未读摘要转述、预算边界及HTTP重定向问题，辅助修订代码、提示和断言 |
| 交付文档 | 生成说明草稿，并根据交付要求调整结构和措辞 |

实现与测试包含 AI 生成和工具执行的内容；协作范围按具体事项记录，不以代码行数或主观比例衡量贡献。

## 验证结果与改进记录

最终[真实模型评估](../examples/live/run-20261107T131207894281Z/report.md)为9/9通过本仓库断言，[自动化测试](../examples/tests/unittest-20261107T131159415747Z.txt)为28项通过；[离线模拟](../examples/mock/run-20261107T130716791849Z/report.md)只验证流程，业务效果未评估。

首次运行的自动检查未覆盖两类问题：冲突场景附加了选择较严格期限的建议；读取失败时转述了未核实的摘要期限。经 AI 辅助复核后，增加相应提示约束和禁止性断言，再次执行验证。旧输出及[事后复核记录](../examples/live/run-20261107T130612599867Z/posthoc-review.json)保留，详细过程见[评估文档](03-evaluation.md)。

逐字引用校验只检查证据来源，固定用例和正则断言也不能证明所有回答在语义上正确。上述结果限定于本仓库的资料与测试范围。
