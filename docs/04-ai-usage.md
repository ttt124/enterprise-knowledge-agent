# AI 使用说明

## 已知分工

| 参与方 | 本次记录支持的工作 |
| --- | --- |
| 用户 | 选择题目方向 3 与 Python；申请模型 API，并在本机配置密钥 |
| Codex 主代理 | 设计、实现和集成程序，组织验证并驱动测试 |
| `gpt-6.1-sol` 子代理 | 分别承担检索模块、测试与评测、文档编写任务 |

子代理实际使用 `gpt-6.1-sol`；业务问答实时调用的模型为 `deepseek-flash`，API 返回的模型名同名。编码助手与被测业务模型分别承担开发辅助和运行时问答职责。

本说明不将 AI 生成的代码或文档描述为用户独立编写。当前记录尚不能证明用户已独立修改程序、解释全部调用链或完成全部验证，也不据此声称已掌握相关技能。

## AI 参与的内容与核对方式

AI 参与需求整理、工具循环与模块设计、示例知识资料、Python 实现、测试用例、评测脚本和说明文档的生成与修订。六份知识资料均为演示而自拟，不构成真实企业制度。

本次对 AI 产出采用以下核对方式：

1. 用源码确认模型请求是否实际进入本地工具执行，再将结果返回模型。
2. 用单元测试检查检索、引用校验、异常和预算边界。
3. 用实时模式记录检查真实模型行为；模拟模式只能检查预设流程。
4. 修改事实并添加冲突资料后重新评测，观察答案是否跟随证据变化。
5. 对照答案、原文和完整 trace 人工检查引用之外的推理错误。

主代理已检查主要调用路径、驱动测试并人工核对主要输出。最终[实时用例](../examples/live/run-20261107T131207894281Z/report.md)业务与证据断言通过 9/9，[单元测试记录](../examples/tests/unittest-20261107T131159415747Z.txt)显示 28 项通过；[模拟用例](../examples/mock/run-20261107T130716791849Z/report.md)流程断言通过 9/9，业务效果不评估。

第一次实时运行的原始自动检查也曾为 9/9，但人工发现 T02 建议按较严格的 15 天执行、T06 转述未成功读取的摘要期限。随后收紧提示和断言，重新运行；旧批次输出与 [posthoc-review.json](../examples/live/run-20261107T130612599867Z/posthoc-review.json)保留，其中 T02、T06 在加强后的断言下失败。该过程说明 AI 产出及自动检查都需要审阅，不能只汇报最后通过数。提示与正则修订仍不构成通用语义正确性证明。
